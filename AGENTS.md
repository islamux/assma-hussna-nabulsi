# AGENTS.md — Project Conventions for AI Coding Agents

## Project Overview

Arabic-language Next.js 16 app displaying 100 grouped names of Allah (Asma Allah Al-Husna) from Dr. Muhammad Ratib Al-Nabulsi's lectures. RTL layout, TailwindCSS 4, TypeScript 5.8.

## Build & Dev Commands

```bash
pnpm install          # Install dependencies
pnpm dev              # Start dev server (Turbopack, port 3000)
pnpm build            # Full build (runs prebuild → build-data.ts → next build)
pnpm start            # Start production server
pnpm lint             # Run ESLint
npx tsx scripts/build-data.ts  # Regenerate data/names.json + search index
```

**IMPORTANT:** Always run `pnpm build` before committing to verify no TypeScript or build errors. The build includes a `prebuild` step that regenerates data from `data/items/`.

## Project Structure

```
src/
├── app/                    # Next.js App Router (file-based routing)
│   ├── layout.tsx          # Root layout — RTL, Arabic fonts, SettingsProvider
│   ├── page.tsx            # Homepage — names gallery
│   ├── globals.css         # TailwindCSS v4 theme (@theme inline), Arabic typography
│   ├── asma/[slug]/page.tsx # Dynamic name pages (100 SSG pages via generateStaticParams)
│   ├── search/page.tsx     # Client-side search (Fuse.js)
│   └── bookmarks/page.tsx  # Bookmarks (localStorage)
├── components/             # Reusable UI components (mix of server and client)
└── lib/
    ├── types.ts            # TypeScript interfaces (NameEntry, NamePart, SearchEntry)
    ├── data.ts             # Server-side data loading (getAllNames, getNameBySlug, getPrevNext)
    ├── bookmarks.ts        # localStorage bookmark CRUD ("use client")
    └── settings-context.tsx # React Context for theme + font size ("use client")

data/
├── items/                  # 190 raw scraped JSON articles (source data, tracked in git)
├── names.json              # 100 grouped names (GENERATED by build-data.ts, gitignored)
└── search-index.json       # Search index (GENERATED, gitignored)

scripts/
└── build-data.ts           # Data pipeline: groups 190 items → names.json + search index
```

## Code Conventions

### Language & Framework
- **TypeScript strict mode** — all types explicit, no `any`
- **Next.js 16 App Router** — server components by default, `"use client"` only when needed
- **React 19** — use modern APIs (no class components)
- **TailwindCSS 4** — CSS-first config via `@theme inline` in globals.css, no tailwind.config.js

### Component Rules
- Server components: no `"use client"` directive (default)
- Client components: add `"use client"` only when using `useState`, `useEffect`, `useContext`, `localStorage`, or browser APIs
- Props interfaces defined inline or at top of file
- One component per file, filename matches export name

### Styling
- Use TailwindCSS utility classes
- Arabic font classes: `.font-heading` (Amiri) for headings, body uses Noto Naskh Arabic
- Theme colors via CSS variables: `--primary`, `--accent`, `--muted`, `--foreground`, `--background`
- Dark mode: `.dark` class on `<html>`, toggled via SettingsContext
- RTL: `dir="rtl"` on `<html>`, no LTR assumptions in layout

### Data Flow
- Source data: `data/items/*.json` (190 scraped articles, tracked in git)
- Build script: `scripts/build-data.ts` groups items by name, sanitizes HTML, generates ASCII slugs
- Generated output: `data/names.json` + `data/search-index.json` (gitignored, built via `prebuild`)
- App reads: `src/lib/data.ts` imports `names.json` directly (server-side only)
- Client search: fetches `/data/search-index.json` via HTTP at runtime

### Naming
- Files: PascalCase for components (`NameCard.tsx`), camelCase for utilities (`data.ts`)
- Arabic slugs: romanized to ASCII (e.g., `alakrm` for `الأكرم`) — Next.js 16 cannot route non-ASCII slugs
- CSS classes: Tailwind utilities + custom `.font-heading`, `.article`, `.pattern-border`

### Error Handling
- No broad `catch {}` — always handle specific errors or let them propagate
- Search page: `.catch()` with error state display
- Bookmarks: localStorage wrapped in try/catch (browser API can throw)
- ShareButton: catch only `AbortError` from Web Share API

### Security
- HTML content sanitized at build time in `build-data.ts` (strips `<script>`, `<iframe>`, event handlers, `javascript:` URIs)
- `dangerouslySetInnerHTML` in ArticleReader is safe because content is pre-sanitized

## What NOT to Do

- Do not add `tailwind.config.js` — this project uses TailwindCSS v4 CSS-first config
- Do not use `npm` — this project uses `pnpm`
- Do not commit generated files (`data/names.json`, `data/search-index.json`, `public/data/search-index.json`) — they are gitignored and built by `prebuild`
- Do not add Arabic characters to URL slugs — Next.js 16 cannot match them
- Do not add `"use client"` to components that don't need browser APIs
- Do not use `style={{ fontFamily: "var(--font-heading)" }}` — use `className="font-heading"` instead
- Do not add comments unless explaining *why*, not *what*
- Do not use `data`, `result`, `item`, `temp`, `value` as variable names without a qualifier

## Key Files to Read Before Editing

- `src/app/globals.css` — theme colors, typography, CSS variables
- `src/lib/types.ts` — data interfaces
- `src/lib/data.ts` — data loading functions
- `scripts/build-data.ts` — data pipeline (edit here to change data structure)

## Deployment

- **Vercel:** `vercel --prod` (auto-detects Next.js, runs `prebuild` then `build`)
- Build generates ~100 static HTML pages
- All pages are pre-rendered at build time (SSG)
